# Free admin screenshot uploads / 免费管理员截图上传

The public site stays on GitHub Pages. A **Cloudflare Worker on the free plan** hosts the password-protected admin panel; **GitHub Actions** runs local Chinese/English Tesseract OCR and republishes reviewed versions. No paid OCR API, database, R2 bucket, or always-on server is required. Cloudflare and GitHub free-plan usage limits apply; standard GitHub-hosted Actions runners are free for this public repository.

公众网站继续使用 GitHub Pages。管理员页面使用 Cloudflare Workers 免费方案，密码在后端校验；GitHub Actions 使用 Tesseract 中英文 OCR 并重新发布核对后的版本。不需要付费 OCR API、数据库、R2 存储桶或常驻服务器，使用量须在免费方案限额内。

## One-time activation / 一次性启用

The implementation is in the repository and tested locally. It cannot accept live uploads until you deploy the Worker and add its secrets. Do not put passwords or GitHub tokens into repository files, this chat, a GitHub repository variable, or the public website.

代码已写入仓库并通过本地测试。须先部署 Worker 并配置机密信息，才能在线上传。密码和令牌只填入 Worker 的加密 Secrets，不能写进仓库、聊天或网站前端。

1. In Cloudflare, open **Workers & Pages → Create application → Import a repository** (the wording may be “Connect Git”). Connect `rititititi/ticketing`. Leave the repository root as it is and set the deploy command to **`npx wrangler deploy --config admin-worker/wrangler.toml`**. No root-directory option is needed. The included `wrangler.toml` configures the admin assets and non-secret repository settings. Use Workers Free.
2. In GitHub, create a **fine-grained personal access token**, scoped to **only `ticketing`**. Grant **Contents: Read and write**, **Actions: Read and write**, and the default **Metadata: Read**. This lets the Worker save screenshots and dispatch the included upload workflow. Set an expiration you can renew.
3. In the Worker’s **Settings → Variables and Secrets**, add these as **Secrets**, then deploy the new version:

   | Secret | What you enter |
   | --- | --- |
   | `ADMIN_PASSWORD` | Your own strong admin password, at least 16 characters |
   | `SESSION_SECRET` | A separate random value of at least 32 characters, generated by a password manager |
   | `GITHUB_TOKEN` | The repository-scoped token from step 2 |

   `GITHUB_OWNER`, `GITHUB_REPO`, `GITHUB_BRANCH` and `SITE_URL` are already non-secret vars in `wrangler.toml`. This workflow expects `main`. Keep tokens only in Worker Secrets.
4. Open the Worker’s `https://uu-scout-admin.<your-subdomain>.workers.dev` URL. Sign in, select a JPG/PNG under **3 MB**, and test an upload. You can also use the panel directly from this URL.
5. To connect the site's **Admin uploads / 管理上传** link, open GitHub **Settings → Secrets and variables → Actions → Variables → New repository variable**. Name it **`UU_SCOUT_ADMIN_URL`** and set its value to the Worker HTTPS URL. This URL is public and is **not** a password or token. Run **Actions → Publish uu scout → Run workflow** once. The site’s upload section will now open your password-protected panel.

中文版步骤：

1. Cloudflare **Workers & Pages → 创建应用 → 导入仓库**，选择 `ticketing`，无需更改根目录，部署命令填 **`npx wrangler deploy --config admin-worker/wrangler.toml`**，选择免费方案。
2. 在 GitHub 创建仅限此仓库的细粒度令牌，权限为 **Contents 读写、Actions 读写、Metadata 读取**。
3. 在 Worker **Settings → Variables and Secrets** 中，将 `ADMIN_PASSWORD`、`SESSION_SECRET`、`GITHUB_TOKEN` 分别保存为加密 **Secret**，然后重新部署。前两项分别使用至少 16 位密码和至少 32 位独立随机字符串。
4. 打开 Worker 的 HTTPS 地址，使用密码登录。
5. 在 GitHub 的 Actions **Variables** 中添加公开配置 **`UU_SCOUT_ADMIN_URL`**，值为 Worker 地址，再手动运行一次 **Publish uu scout**。不要将密码或令牌填入此公开变量。

CLI alternative, if you already use Wrangler:

```sh
cd admin-worker
npx wrangler deploy
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put SESSION_SECRET
npx wrangler secret put GITHUB_TOKEN
```

These commands prompt securely; do not put the values directly in shell commands. For browser-only use, the Cloudflare dashboard path above is sufficient. Keep the **Process admin screenshot** GitHub workflow enabled. If your repository has branch rules blocking direct commits, allow this uploader through your normal repository policy before use; failed pushes leave the current public catalog unchanged.

## Day-to-day use / 日常使用

1. Open the site's **Admin uploads / 管理上传** link and enter your password.
2. Choose **New independent sheet / 新的独立表格**, or select the exact current screenshot that this image updates. Do not link different suppliers just because seats look alike.
3. Upload the screenshot. Keep the displayed job ID; the panel can resume it after a refresh or later login. OCR usually needs a few minutes while the GitHub runner starts.
4. Compare the full image with the editable table. Correct **区域 / 区**, **排 / 排数**, **座位号**, prices and sold boxes. Add missing option rows and delete mistakenly extracted headings/footnotes. Keep ranges such as `15/16/17` together. Leave unconfirmed years/dates blank. OCR alone does not establish completeness or availability.
5. Confirm you checked every option, then click **Publish reviewed version / 发布已核对版本**. The site rebuilds automatically. The panel reports the repository result; the Pages workflow must also finish successfully before visitors see the change.

上传的截图会成为此公开 GitHub 仓库中的文件，包括发布前的 OCR 待核对资料。请只上传打算公开分享的表格。

An exact duplicate image is rejected. A changed sheet becomes a **new version**: the older image and its tickets stay in history, hidden from the normal current view. Visitors can enable **Include older versions / 显示旧版本**. Only explicit sold text or your checked sold boxes mark an option sold; missing rows and red color alone do not. Updating a version that already has a newer version is rejected, so two pending uploads cannot silently replace each other.

完全相同的图片不会重复导入。更新截图会生成新版本，旧图和旧记录保留为历史，默认不显示。新版缺少某行、或只有红色标记，都不会自动判定为已售。若旧版已有更新，须选择最新版本再上传。

**Timing and recovery:** If dispatching fails, use the job's Retry button after fixing token access. If OCR fails, try a clearer crop with headings visible. If a publish review error appears, correct it before retrying. Check the GitHub workflow logs for repository/branch-permission failures. Refreshes keep the job ID in this browser tab; copy it to resume elsewhere. Rotate `SESSION_SECRET` to invalidate all existing sessions when needed.

## Review existing tickets / 核对现有票源

The deployed admin panel now has **Review existing tickets / 核对现有票源**, beside Screenshot uploads. It uses the existing password and GitHub token; no additional service or secret is required. If Cloudflare is connected to this repository, its Git build should redeploy the changed Worker and assets. Otherwise open the existing Worker in Cloudflare, choose **Deployments → Retry deployment** for the latest Git commit, using the same deploy command above. Keep the **Publish admin ticket corrections** workflow enabled.

1. Sign in and choose **Review existing tickets**. Choose a current screenshot, then **Needs review** or **All records on this page**. Large sheets have Previous/Next page controls (100 records per page).
2. Click **View row** to inspect the original row pixels and retained OCR. You can also open the full screenshot. OCR text is evidence and may be incorrect.
3. Edit the printed row and seat text without splitting ranges or inventing an exact seat. Set availability to **Unknown**, **Available**, **Sold out**, **Paid**, or **Locked**. Unknown and blank fields remain unresolved. Original quotes are preserved in the audit if a ticket is marked sold; marking an originally sold record available does not invent a missing quote.
4. Select only the records you checked, add an optional public review note, tick the explicit confirmation, and choose **Approve selected records**. Corrections and notes are public repository data. This approves row/seat/stock fields only, not every OCR price or date.
5. GitHub Actions validates revisions, records before/after values, refreshes coverage and the public updates feed, and deploys Pages. The panel shows publication status. If a record or screenshot changed meanwhile, reload it and review again; stale edits are rejected.

After a browser refresh the same tab can resume a pending review job. The job ID is displayed for reference. Failed/transient workflow dispatches have a Retry publication button. Keep the tab open until the publication result appears; a failed job may need the GitHub Actions log checked.

The original screenshots and `data/updates` patches remain unchanged. Approved corrections live in append-only `data/reviews/<job>.json` audit files. `build_draft2.py` replays these reviews after screenshot imports, so subsequent catalog rebuilds retain approved corrections. The queue's bounded source pages under `data/admin-review` avoid the GitHub Contents API's large-JSON limit.

管理员登录后，选择“核对现有票源”，按原图检查选中的排号、座位及状态。确认后发布，系统保存核对前后值并重新生成网站。“未知”或留空不会变为已确认；只核对这些字段，不会自动确认价格和日期。若记录已被他人更新，旧核对请求将被拒绝，须重新加载。无需新增账户或密钥；若未看到新入口，请在 Cloudflare 对最新 Git 版本重新部署现有 Worker。
